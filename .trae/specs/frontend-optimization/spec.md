# 旺财百宝箱 - 前端优化与港股打新增强 PRD

## Overview
- **Summary**: 对小程序前端进行数据绑定联动优化，消除硬编码与随机数兜底；参考捷利交易宝重构港股打新板块，新增暗盘行情、券商孖展、超额认购、配售结果等核心功能，打造一站式港股打新体验。
- **Purpose**: 当前前端存在数据绑定不联动、字段命名中英文混用、日期/数据硬编码、随机数兜底等问题；港股打新板块功能过于简陋，仅有基础列表，缺少捷利交易宝式的暗盘、孖展、认购倍数等打新核心数据。本次优化旨在提升数据一致性和用户体验。
- **Target Users**: 使用旺财百宝箱进行可转债、LOF基金、港股打新投资的个人投资者。

## Goals
- 消除前端硬编码日期和随机数兜底，实现数据驱动渲染
- 统一前后端字段命名，消除中英文混用的兼容代码
- 实现首页与各子页面的数据绑定联动（自选、申购状态跨页面同步）
- 参考捷利交易宝，重构港股打新板块，新增暗盘行情、券商孖展、超额认购倍数、配售结果等功能
- 港股打新新增详情页，展示完整发行流程和关键数据
- 打新日历改为动态生成，基于真实数据渲染

## Non-Goals (Out of Scope)
- 不修改后端 API 架构（已有 backend-api-design spec 负责）
- 不新增数据源（efinance/tushare 等由后端 spec 处理）
- 不实现真实交易下单功能
- 不实现 Lv2 实时行情（需付费数据源）
- 不修改用户认证和数据库持久化（Phase 3 范围）
- 不修改云函数和 CloudRun 后端代码

## Background & Context
- 项目为微信小程序，采用"云函数 + CloudRun Flask 后端 + akshare 数据源"混合架构
- 前端已有首页、可转债、LOF、港股打新四个主页面 + 可转债详情页
- 后端 `hk_ipo.py` 仅提供基础列表数据（code/name/ipo_price/status/list_date/change_pct），缺少 lot_size、win_rate、孖展、暗盘等字段
- 捷利交易宝是港股打新领域的标杆产品，核心功能包括：新股信息、暗盘行情、券商孖展资金分布、配售结果、超额认购倍数、AiPO打新记
- 前端各页面字段命名混乱，如可转债页面需同时兼容 `item['转债价格']` 和 `item.price`，LOF 页面需兼容 `item.premium || item['溢价率']`

## Functional Requirements

### FR-1: 数据绑定联动优化
- **FR-1.1**: 移除首页 `index.js` 中所有硬编码日期（`const today = '2026-06-24'`、`'2026-06-26'` 等），改为 `new Date()` 动态获取
- **FR-1.2**: 移除首页 `generateTimeline` 中的硬编码兜底日期，当后端未返回 timeline 数据时显示"暂无流程信息"
- **FR-1.3**: 移除可转债页面 `formatBondItem` 中的随机数兜底（`8 + Math.random() * 15` 等），未获取到数据时显示 `--`
- **FR-1.4**: 移除首页 `loadData` 中 `win_rate` 的随机生成逻辑，未获取到时显示 `--`
- **FR-1.5**: 打新日历改为动态生成，基于 `ipoDrawList` 中的 `apply_end_date`、`draw_date`、`list_date` 渲染日历标记
- **FR-1.6**: 首页港股打新卡片"已上市"标签改为"近期上市"，与实际数据含义匹配

### FR-2: 字段命名统一
- **FR-2.1**: 前端统一使用英文字段名（`bond_code`、`price`、`premium_rate` 等），移除中文字段兼容代码（`item['转债价格']` 等）
- **FR-2.2**: LOF 页面统一使用英文字段名（`code`、`name`、`price`、`premium` 等），移除 `item['溢价率']` 兼容
- **FR-2.3**: 港股打新页面统一使用英文字段名，与后端 normalizer 标准化字段一致

### FR-3: 跨页面数据联动
- **FR-3.1**: 自选股状态跨页面同步——在港股打新页面添加/取消自选后，首页和自选管理页面同步更新
- **FR-3.2**: 申购状态跨页面同步——首页标记的申购/中签状态在港股打新页面也可见
- **FR-3.3**: 使用事件总线或 `app.globalData` 实现跨页面状态通知

### FR-4: 港股打新 - 列表增强
- **FR-4.1**: 港股打新列表增加 Tab 分类：全部 / 申购中 / 待上市 / 已上市 / 暗盘中
- **FR-4.2**: 列表项增加关键字段展示：发行价、每手股数、申购截止日、上市日、超额认购倍数、暗盘涨跌幅
- **FR-4.3**: 列表项支持点击进入详情页
- **FR-4.4**: 列表支持按超额认购倍数、暗盘涨跌幅排序

### FR-5: 港股打新 - 详情页（参考捷利交易宝）
- **FR-5.1**: 新建港股打新详情页 `hkipoDetail`，展示单只 IPO 完整信息
- **FR-5.2**: 详情页包含：基本信息（名称/代码/行业/发行价/每手股数/发行规模/市盈率）
- **FR-5.3**: 详情页包含：发行流程时间线（递表→聆讯→招股→截止→中签→上市），动态渲染
- **FR-5.4**: 详情页包含：认购数据（超额认购倍数、孖展认购额、公开认购倍数、国际配售倍数）
- **FR-5.5**: 详情页包含：暗盘行情（暗盘价、暗盘涨跌幅、暗盘时间）
- **FR-5.6**: 详情页包含：配售结果（一手中签率、申购倍数、配售回拨比例）
- **FR-5.7**: 详情页包含：上市表现（首日开盘价、首日收盘价、首日涨跌幅、累计涨跌幅）
- **FR-5.8**: 详情页支持添加/取消自选和申购状态标记

### FR-6: 港股打新 - 暗盘行情模块
- **FR-6.1**: 港股打新页面新增"暗盘行情"卡片，展示当日暗盘交易中的新股
- **FR-6.2**: 暗盘卡片展示：新股名称、暗盘价、暗盘涨跌幅、发行价对比
- **FR-6.3**: 暗盘数据不足时显示"暂无暗盘数据"占位

### FR-7: 港股打新 - 券商孖展模块（参考捷利交易宝）
- **FR-7.1**: 详情页新增"券商孖展"模块，展示各券商孖展认购金额和倍数
- **FR-7.2**: 孖展模块展示：券商名称、孖展金额、占比、累计倍数
- **FR-7.3**: 孖展数据不足时显示"暂无孖展数据"占位

### FR-8: 港股打新 - 打新日历增强
- **FR-8.1**: 首页打新日历改为动态生成当月日历
- **FR-8.2**: 日历根据 `ipoDrawList` 数据在对应日期标记申购(●)、抽签(▲)、上市(★)图标
- **FR-8.3**: 日历支持点击日期查看当日所有打新事件
- **FR-8.4**: 日历支持月份切换（上月/下月）

## Non-Functional Requirements
- **NFR-1**: 页面首屏渲染时间 < 1.5s（含数据加载）
- **NFR-2**: 列表滚动流畅，60fps 无卡顿
- **NFR-3**: 支持暗夜模式，所有新增组件需适配 dark-mode 样式
- **NFR-4**: 所有新增页面需适配不同屏幕尺寸（iPhone SE ~ iPhone 15 Pro Max）
- **NFR-5**: 数据加载失败时显示友好的错误提示和重试按钮，不使用 Mock 数据静默兜底

## Constraints
- **Technical**: 微信小程序框架（WXML/WXSS/JS），不支持 TypeScript
- **Technical**: 后端 API 字段标准化依赖 backend-api-design spec 的实施进度，前端需做过渡兼容
- **Business**: 暗盘行情、券商孖展等数据需要后端 akshare 接口支持，部分数据可能无法获取
- **Dependencies**: 后端 `hk_ipo.py` 需扩展返回字段（lot_size, win_rate, oversubscription, margin_data 等）

## Assumptions
- 后端 `hk_ipo.py` 将扩展返回字段，前端按新字段开发，旧字段做过渡兼容
- 暗盘行情和券商孖展数据在 akshare 中有对应接口或可由后端补充 Mock 数据
- 打新日历的数据来源为 `hkipoList` 和 `hkipoUpcoming` 接口返回的日期字段
- 跨页面状态同步使用 `app.globalData` + 页面 `onShow` 刷新的简单方案，不引入额外状态管理库

## Acceptance Criteria

### AC-1: 消除硬编码日期
- **Given**: 首页 `index.js` 代码中存在硬编码日期 `'2026-06-24'`、`'2026-06-26'`
- **When**: 审查首页代码
- **Then**: 所有日期均通过 `new Date()` 动态获取或从后端数据中读取，代码中不存在硬编码的日期字符串
- **Verification**: `programmatic`

### AC-2: 消除随机数兜底
- **Given**: 可转债页面 `formatBondItem` 中 `hundredRightValue` 使用 `8 + Math.random() * 15` 兜底
- **When**: 后端未返回 `百元含权` 字段时
- **Then**: 显示 `--`，不使用随机数生成假数据
- **Verification**: `programmatic`

### AC-3: 打新日历动态渲染
- **Given**: 首页打新日历当前为硬编码的 2026年6月日历
- **When**: `ipoDrawList` 数据加载完成
- **Then**: 日历根据数据中的 `apply_end_date`、`draw_date`、`list_date` 在对应日期显示申购、抽签、上市标记
- **Verification**: `human-judgment`

### AC-4: 港股打新详情页
- **Given**: 用户在港股打新列表点击某只新股
- **When**: 跳转到详情页
- **Then**: 展示基本信息、发行流程时间线、认购数据、暗盘行情、配售结果、上市表现等完整信息
- **Verification**: `human-judgment`

### AC-5: 暗盘行情模块
- **Given**: 港股打新页面加载完成
- **When**: 存在暗盘交易中的新股时
- **Then**: 展示暗盘行情卡片，显示新股名称、暗盘价、暗盘涨跌幅
- **Verification**: `human-judgment`

### AC-6: 券商孖展模块
- **Given**: 用户进入港股打新详情页
- **When**: 该新股有孖展数据时
- **Then**: 展示券商孖展列表，含券商名称、孖展金额、占比、累计倍数
- **Verification**: `human-judgment`

### AC-7: 跨页面自选同步
- **Given**: 用户在港股打新页面添加了一只新股自选
- **When**: 切换到首页或自选管理页面
- **Then**: 该自选状态已同步，无需手动刷新
- **Verification**: `human-judgment`

### AC-8: 字段命名统一
- **Given**: 可转债页面 `formatBondItem` 需兼容 `item['转债价格']` 和 `item.price`
- **When**: 审查前端代码
- **Then**: 统一使用英文字段名 `item.price`，移除中文字段兼容代码
- **Verification**: `programmatic`

### AC-9: 港股打新列表增强
- **Given**: 港股打新页面加载完成
- **When**: 展示列表
- **Then**: 每个 IPO 项展示发行价、每手股数、申购截止日、超额认购倍数、暗盘涨跌幅等关键字段，支持 Tab 分类和排序
- **Verification**: `human-judgment`

### AC-10: 申购状态跨页面同步
- **Given**: 用户在首页标记某只 IPO 为"已申购"
- **When**: 进入港股打新页面
- **Then**: 该 IPO 的申购状态已同步显示
- **Verification**: `human-judgment`
