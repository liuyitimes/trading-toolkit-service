## ADDED Requirements

### Requirement: LOF 溢价日度观测持久化

服务 MUST（必须）以 PostgreSQL 持久化 LOF 溢价日度观测，并以基金代码和交易日作为唯一键。每条观测必须保存同日收盘价、已公布单位净值、溢价率、价格与净值来源、来源 URL、实际净值日期、写入来源、版本和审计时间；开发与测试环境必须保持 SQLite 兼容。

#### Scenario: 同一交易日重复采集

- **当**：同一基金和交易日再次得到有效且更新的来源数据
- **则**：服务必须幂等更新同一观测并增加修订审计信息
- **并且**：不得新增第二条同基金、同交易日记录

### Requirement: 同日可比性与交易日历

服务 MUST（必须）使用由沪深交易所官方年度休市安排导入的 PostgreSQL A 股交易日历，作为采集、回补、缺口和连续性计算的唯一日期口径。只有价格日期与实际净值日期一致时，服务才可以写入日度观测；周末和交易所共同休市日不得构成缺口。

#### Scenario: 价格与净值日期不一致

- **当**：某 LOF 的价格日期与实际净值日期不一致
- **则**：服务不得为该日期写入日度观测
- **并且**：持续性结果必须以不可用或历史不足状态说明该日期不可比

### Requirement: 历史回补和日度采集任务

服务 MUST（必须）提供可断点续跑的当前自然年回补任务和交易日收盘后采集任务。回补必须覆盖当前有效 LOF 的完整范围，以东方财富历史单位净值和腾讯历史日收盘价的同日交集写入 `backfill` 观测；日度采集必须在中国标准时间 20:30 至 23:30 的窗口运行。两类任务必须记录 PostgreSQL 进度并由数据库锁防止同类任务并行运行。

#### Scenario: 回补任务中断后恢复

- **当**：当前年度回补任务在部分基金完成后失败或被中断
- **则**：后续同范围任务必须从已记录游标恢复
- **并且**：不得重复创建已写入的观测

#### Scenario: 非交易日触发采集

- **当**：外部调度器在交易所共同休市日调用日度采集任务
- **则**：任务必须完成而不写入观测
- **并且**：不得将该日期记为数据缺口

### Requirement: 连续正溢价计算

服务 MUST（必须）从原始日度观测批量计算连续正溢价，不得以独立缓存表作为事实来源。当前同日可比且溢价非正时，连续天数必须为零且状态为 `complete`；当前不可比时状态必须为 `unavailable`；已覆盖交易日出现缺口，或正溢价序列触及当前年首次回补边界时，状态必须为 `partial` 并返回已观测下界与原因。

#### Scenario: 正溢价序列跨越周末

- **当**：某基金在周五和下一个交易日均有连续的同日正溢价观测
- **则**：周末不得中断其连续天数
- **并且**：结果状态必须保持 `complete`

#### Scenario: 已覆盖交易日出现缺口

- **当**：交易日历标识某日开市但该基金缺少可比观测
- **则**：缺口后的正溢价序列必须返回 `partial`
- **并且**：结果必须包含缺失交易日原因
