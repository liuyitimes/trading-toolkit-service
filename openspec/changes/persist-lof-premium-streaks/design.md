## Context

当前 LOF 服务仅返回当前行情，且错误地将净值日期设为行情时间；没有连续正溢价的观测、任务或 API 契约。配套 Web 已有展示列但把字段缺失回退为 `0`。本变更使用现有 SQLAlchemy、Alembic、`em_get` 和 `tencent_get`，不引入未经验证的数据源。

## Goals / Non-Goals

**Goals:**

- 建立可审计、可修订、可跨重启和多实例保留的 LOF 日度观测。
- 使用官方交易日历和同日价格/净值配对，可靠计算连续正溢价。
- 通过外部调度器和幂等任务完成当前年度回补和日度采集。

**Non-Goals:**

- 推断盘中估值、当前年以前的历史或可执行套利。
- 将后台采集放入列表读取请求或 Flask 进程内定时器。
- 构建独立的持续性缓存事实表。

## Decisions

- PostgreSQL 是生产事实源，SQLite 保持测试兼容；Alembic 创建 `trading_calendar`、`lof_premium_observation` 和 `lof_premium_job`。JSON 和 Redis 被排除，因为它们不能同时保证多实例一致性、审计和迁移。
- `trading_calendar` 存储官方年度交易日。计算只检查该表中的开市日，避免周末和节假日成为假缺口。
- `lof_premium_observation` 以 `(fund_code, trading_date)` 唯一；有效更正执行版本化 upsert。连续性使用批量查询从原始观测计算，三年规模无需物化读模型。
- 回补将东方财富 `lsjz` 历史单位净值与腾讯日 K 线收盘价按日期交集配对，范围为当前有效 LOF 和当前自然年。首次覆盖边界与采集缺口均产生 `partial`，而非假定完整历史。
- 每日任务由可移植 Flask CLI 命令运行，外部 `systemd timer` 或平台 Cron 调用。PostgreSQL 任务行与 advisory lock 提供互斥、游标和恢复；收集窗口为 20:30 至 23:30（中国标准时间）。

## Risks / Trade-offs

- [上游历史源限流或字段变更] → 通过既有 HTTP 客户端限流、每基金游标和可恢复任务降低影响；失败不写零值。
- [官方日历导入延迟] → 任务拒绝在未知日期推断开市，状态记录为不可用或历史不足。
- [当前年回补边界限制长期连续性] → 触及边界时明确返回 `partial`、起点与原因。
- [同日净值晚于窗口可用] → 在 23:30 前重试，仍无同日净值时保持缺口并允许后续修订补齐。

## Migration Plan

1. 执行 Alembic 迁移并导入当前年度交易日历。
2. 部署 API 与 CLI 命令，配置外部日度定时器但不在读取接口写入观测。
3. 执行一次当前年度回补，检查任务状态、失败基金和 `partial` 覆盖边界。
4. 部署配套 Web 变更后验证列表状态展示。
5. 回滚时停用外部任务并恢复旧客户端展示；保留数据库表和观测数据以便审计与再次启用。
