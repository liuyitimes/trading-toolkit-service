# 提案：公告驱动的首日可交易量

## 背景

待配债接口目前在巨潮公告尚未同步时把 `tradable_amount` 设为发行规模，并把原股东配售率设为 0。这会把未知事实误显示成已知数据，导致首日流通量和配售评分失真。

## 目标

在后台配债刷新中自动同步巨潮资讯发行结果/优先配售公告。公告披露“原股东优先配售合计”后，服务用该值计算首日可交易量；公告不存在或解析失败时返回 `null`，前端统一显示 `--`。

## 范围

- 服务端公告定向检索、PDF 解析结果复用、快照字段覆盖和缺失状态。
- Web 端对未知配售率和首日可交易量的准确展示。
- 记录“公告发布前无法获取股东配售量”的数据缺口。

## 非目标

- 不拆分大股东、实际控制人和其他原股东。
- 不根据锁定期或股东身份额外推断可交易量。
- 不在用户 HTTP 请求中下载公告 PDF。

## 配套变更

Web 仓库存在同名 `placement-tradable-amount-announcement` 变更，仅负责客户端展示和契约测试。
