# LOF 场内规则证据库

## 背景

当前 LOF 列表仅从空的本地 JSON 读取申赎时效，无法对基金级场内规则建立可追溯事实，也无法在规则缺失时区分未获取、过期和冲突。用户需要全量建立当前有效场内 LOF 的规则库，同时保持连续溢价历史回补只覆盖当前溢价前 20。

## 变更内容

- 新增版本化 LOF 场内规则、原始证据和采集任务的数据库事实来源。
- 新增全量建库与当前前 20 状态刷新命令；缺失规则也建档并可增量重试。
- 仅从满足代码/份额类别、场内渠道、时间语义与生效条件的确定性证据写入 `T+n` 和最低申/赎。
- 扩展 LOF 列表与详情契约，返回场内申赎时效、最低申/赎及证据状态。

## 能力

### 新增能力

- `lof-execution-rules`: LOF 场内规则证据库、采集与规则解析。

### 修改能力

- `lof-funds`: LOF 列表和详情返回当前有效的场内规则事实。

## 影响

- 影响 `cloudrun/models`、`services/lof_fund.py`、新增规则采集服务和 CLI。
- SQLite 本地运行时通过模型建表创建新增表；PostgreSQL 部署通过 Alembic 迁移。
- HTTP 响应只新增可选字段，配套 Web 变更为 `lof-execution-rules-registry`。
- 回滚时停止规则任务并忽略新增可选字段；保留证据表供审计，不删除既有行情和溢价观测。
