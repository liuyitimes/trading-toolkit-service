## ADDED Requirements

### Requirement: LOF 场内规则证据库
服务 MUST 为当前有效且具备场内份额的 LOF 建立按交易所代码和份额类别区分的版本化场内规则证据库。规则 MUST 保存来源、适用范围、生效区间和解析状态；同名基金或其他份额类别不得自动继承规则。

#### Scenario: 全量建库遇到缺失材料
- **GIVEN** 当前有效 LOF 未找到满足证据门槛的材料
- **WHEN** 执行全量建库
- **THEN** 服务创建该代码和份额类别的采集记录并记录检索时间、来源和未获取原因
- **AND** 不写入默认 T+n、最低申购或最低赎回值

#### Scenario: 通用场内规则适用
- **GIVEN** 交易所或中登正式材料明确适用于目标市场全部 LOF
- **WHEN** 目标代码没有更高优先级的专项字段
- **THEN** 服务可以将该字段解析为目标代码的当前规则
- **AND** 证据保留其通用适用范围

### Requirement: LOF 场内时效确定性解析
服务 MUST 只从明确覆盖目标代码或合格通用范围、场内渠道、字段语义和生效条件的证据解析场内申购确认 T+n、场内赎回到账 T+n 与最低申/赎。T+n 仅可使用原文明示值或同一证据的日期与 A 股交易日历确定性推导。

#### Scenario: 证据明确给出日期边界
- **GIVEN** 同一场内规则证据明确给出申请日和确认日或到账日
- **WHEN** 服务解析时效
- **THEN** 服务按 A 股交易日历计算 T+n 并保存原始日期和来源
- **AND** 不使用自然日或行业经验替代交易日结果

#### Scenario: 证据属于场外渠道或条件不完整
- **GIVEN** 材料只描述场外直销/代销，或缺少目标范围、时间语义或生效条件
- **WHEN** 服务解析规则
- **THEN** 对应场内字段保持未获取
- **AND** 不将该材料复制到场内规则

### Requirement: LOF 规则版本与冲突处理
服务 MUST 按生效区间保留规则版本，并以专项公告、合同/招募说明书、管理人产品页、交易所或中登通用规则的顺序解析当前字段。同优先级且值冲突的字段 MUST 保持待核验。

#### Scenario: 新专项公告修改旧规则
- **GIVEN** 新专项公告明确覆盖目标字段且已生效
- **WHEN** 服务重新解析当前规则
- **THEN** 列表和详情使用新公告字段
- **AND** 旧证据和规则版本仍可审计

#### Scenario: 同优先级材料冲突
- **GIVEN** 两份同优先级且当前有效的材料对同一字段给出不同值
- **WHEN** 服务解析当前规则
- **THEN** 服务不自动选择任一值
- **AND** 返回待核验状态和冲突原因

### Requirement: LOF 规则采集调度范围
服务 MUST 支持全量规则建库和状态刷新两个可恢复任务。静态规则全量建库后按公告增量更新；状态刷新仅处理任务启动时当前有效报价溢价率前 20 的 LOF。

#### Scenario: 收盘后状态刷新
- **GIVEN** 收盘后任务开始且当前市场有有效 LOF 报价
- **WHEN** 执行状态刷新
- **THEN** 服务仅请求当前溢价前 20 的状态材料
- **AND** 范围外基金的静态规则不被删除或改写
