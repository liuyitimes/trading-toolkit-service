## 一、已确立的偏好与约定

### 1.1 数据备份规范

- 本项目产生的金融资料（IPO 文件、公司年报等）须备份到 `D:\笔记\ObsVault\投资日记`
- 今后所有金融类开发任务产生的资料，默认在此目录保留一份

### 1.2 命名规范

- 后端 API 统一使用 **英文 snake_case** 字段名（如 `bond_code`、`premium_rate`）
- 前端直接使用英文字段，不再兼容中文 key
- 后端 `normalizer.py` 负责将数据源的中文字段标准化为英文
- 底层数据源模块（`convertible_bond.py`、`lof_fund.py` 等）直接输出英文 key

### 1.3 响应格式

所有 API 统一返回：

```json
{
  "success": true,
  "data": { ... },
  "meta": {
    "cached": true,
    "source": "akshare",
    "update_time": "2026-06-25T10:25:00+08:00"
  }
}
```

### 1.4 接口版本

- 所有接口以 `/api/v1/` 为前缀
- 保留旧路径 `/api/*` 的向后兼容路由
- 未来大版本升级使用 `/api/v2/`

## 二、架构决策

### 2.1 部署策略：最低成本方案

**当前阶段（开发）**：本地 Flask 后端 + 小程序预览

**上线方案**：纯云函数 + 云数据库（零服务器费用）

> 砍掉 Docker / 云托管以节省成本。云函数按月免费额度（40 万次/月）足够个人项目使用。上线时将 `cloudrun/` 的 Python 逻辑迁移到云函数。

### 2.2 数据存储分层

```
L1 内存缓存 (Python dict / lru_cache)  ← 实时行情，5s~30min
L2 缓存 (fakeredis 开发 / Redis 生产)   ← 分钟级数据
L3 持久化 (SQLite 开发 / PostgreSQL 生产) ← 基础信息 + 计算结果
L4 用户数据 (当前 wx.Storage / 未来云数据库) ← 自选/提醒/设置
```

- 现阶段**不需要分库分表**（数据量小、单机部署）
- 触发条件：单表 > 50 万行 或 需要多服务并发写入时再拆分

### 2.3 数据源体系

| 优先级 | 数据源 | 可转债 | LOF | 港股IPO | 市场情绪 | 费用 |
|--------|--------|--------|-----|---------|----------|------|
| 1（主） | akshare | 新浪 + 东方财富 | 东方财富 ETF | 同花顺 | 新浪 + 乐咕 | 免费 |
| 2 | efinance | 东方财富直连 | 东方财富直连 | 基础支持 | 不支持 | 免费 |
| 3 | tushare | 仅基础信息 | 仅基础信息 | 不支持 | 指数数据 | 需 Token |
| 4（兜底） | mock | 18 条示例 | 10 条示例 | 4 条示例 | 静态数据 | 免费 |

**降级链**：`akshare → efinance → tushare → mock`

**熔断策略**：连续失败 5 次 → 熔断 60 秒

### 2.4 可转债数据合并

- **新浪源** (`bond_zh_hs_cov_spot`)：320+ 条活跃可转债，实时价格/涨跌幅/成交量
- **东方财富源** (`bond_zh_cov`)：1029 条，含溢价率/转股价值/评级/发行规模
- 两源按 `bond_code` 合并，溢价率覆盖率 99.7%（原 JSL 源仅 10%）
- `_merge_bond_data()` 内部统一英文 key，`get_convertible_bond_list()` 直接输出英文

### 2.5 分级缓存 TTL

| 数据等级 | 示例 | 交易时段 TTL | 非交易时段 TTL |
|----------|------|-------------|---------------|
| T+0 实时 | 股票行情、可转债现价 | 30~60s | 30~60s |
| 日内快照 | 情绪、资金流向 | 5~10min | 4h |
| 日线数据 | 可转债列表、LOF、港股IPO | 15~30min | 4h |
| 日终数据 | 市场温度、信号、套利机会 | 15min | 4h |
| 低频数据 | 可转债详情、股票基本信息 | 12h | 12h |

缓存后端优先级：**Redis** → **fakeredis**（开发环境） → **内存 LRU**（兜底，最大 500 条）

缓存防穿透：双重检查锁机制，同一 key 只有一个请求回源。

## 四、调用链路

### 4.1 当前（开发阶段）

```
小程序 → cloudApi.js
  → ① HTTP localhost:8080 (Flask)
    → fetch_with_cache (缓存)
      → DataSourceFactory.get_with_fallback (降级链)
        → akshare → efinance → tushare → mock
  → ② 降级到云函数 (Node.js, 当前也走Mock)
  → ③ 前端 Mock 兜底
```

### 4.2 目标（上线后）

```
小程序 → cloudApi.js
  → Python 云函数
    → 内存缓存
    → akshare 直接爬数据
    → 返回真实数据
```
