# 领域文档

本文件说明工程技能如何使用本仓库的领域资料。

## 开始调研前

先阅读与任务相关的下列资料：

- `docs/domain/` 中的领域规则与计算口径。
- `docs/architecture/` 中的模块职责、数据源与基础设施决策。
- `openspec/specs/` 中当前受支持的行为规范。
- 仓库根目录的 `CONTEXT.md` 和 `docs/adr/`；若后续建立这些文件，也应一并阅读。

尚未创建的可选目录不构成错误。只有在领域术语或架构决策已明确时，才创建或更新相应资料。

## 布局

本仓库采用单上下文布局：

```text
/
|- cloudrun/
|- docs/architecture/
|- docs/domain/
|- openspec/specs/
`- backtest/
```

## 使用既有术语

在问题、提案、假设或测试中命名领域概念时，优先使用 `docs/domain/` 与相关 OpenSpec 规范中定义的术语。若缺少必要概念，先确认既有术语是否适用；确有缺口时，记录待补充的领域建模工作。

## 标记架构冲突

提议的变更与既有架构文档或 ADR 相冲突时，必须显式说明冲突，不得静默覆盖原决策。
