# LOF 溢价日度观测使用 PostgreSQL

状态：已接受。LOF 溢价日度观测使用现有 PostgreSQL 持久化，并通过 Alembic 管理结构变更；开发与测试可沿用现有 SQLite 兼容路径。相较 JSON 文件和 Redis，该选择能保证重启与多实例后的历史连续性、以基金代码和交易日实现幂等写入，并让连续正溢价计算可审计且可查询。

后果是采集任务必须在交易日 `20:30–23:30`（中国标准时间）运行，且与读接口分离；市场观测写入失败不得由缓存或零值替代。同一基金、交易日的上游修订以可审计幂等更新写入，并触发该基金后续连续序列重算。原始观测保留三年并按交易日清理。观测数据属于可重建市场数据，不承诺灾备恢复，与 ADR-0002 的持久化边界保持一致。

历史回补以东方财富历史单位净值与腾讯历史日收盘价的同日交集为唯一输入，并分别保留来源与导入时间；首次导入只覆盖当前自然年。现有实时采集必须保存上游实际净值日期，而不得以行情时间替代。

采集和回补实现为可移植的幂等任务命令，由 Ubuntu `systemd timer` 或目标平台的 Cron 调度。PostgreSQL 记录任务进度并提供互斥锁；不使用 Flask 进程内线程或定时器承载任务调度。
